【第2回：通信方式の選び方・設計編】
====================================================================

タイトル：
自作オンラインゲームの通信方式を模索して、専用サーバー（TCP＋Oracle Cloud）に辿り着くまでの話

本文：
個人開発でオンライン対戦ゲームを作ろうとしたとき、最初に悩むのが「どうやって2人のプレイヤーを繋ぐか？」という通信方式の選択です。

私も自作の3Dダイス対戦ゲーム（C++ / DirectX11）をオンライン対応させるにあたり、最初は「片方のプレイヤーのPCをサーバー役にする方式（リッスンサーバー型）」で実装し、そこから「Oracle Cloud 上に専用の中継サーバーを立てるハイブリッド構成」へと進化させました。

この記事では、以前実装していた方式でぶつかった壁と、それをどう乗り越えて今のサーバー構成に辿り着いたのかをまとめます。

1. 最初に実装していた「ホスト（プレイヤー1）＝サーバー役」方式

オンライン対応の第一歩として最初に組んだのは、1P（ホスト）のPC自体がサーバー役を兼ねるクライアント・サーバー型（いわゆるリッスンサーバー方式）でした。

当時の役割分担は以下の通りです。
・プレイヤーの役割：
ホスト（1P）が部屋を作成して待機し、クライアント（2P）が参加者として接続する。
・接続の確立：
ホスト側が自分のPCのポート番号を開放して待ち受け、クライアント側はホストから教えられたIPアドレスを直接入力して接続を要求する。
・盤面の絶対同期（★ここがこだわり）：
ホストが物理演算やゲーム状態などのマスターデータを持ち、定期的に現在状況を送信することで、クライアント側の画面上の状態を強制上書きしてズレを補正する。
・アクションの同期：
お互いのターンのダイス出目やコマの移動をパケットでやり取りする。

うまくいった点と、ぶつかった壁

この方式で作った「ホストがマスターデータを持ち、定期同期でズレを強制補正する仕組み」自体は非常に強力で、対戦中の同期ズレを防ぐ要として完璧に機能しました。

しかし、いざ離れた友達や不特定多数の人に遊んでもらおうとすると、接続の確立部分に大きな壁がありました。
1. PCのポート開放（ルーター設定）のハードルが高すぎる
ホストになるプレイヤーが毎回ルーターの設定画面を開いてポート開放をしなければならず、環境によってはそもそもポートを開けられないケースがありました。
2. IPアドレスを毎回教えて直打ちしてもらう手間とセキュリティ不安
遊ぶたびにホストのグローバルIPアドレスをチャット等で教え、クライアント側に入力してもらう必要があり、プライバシー面でも気軽に遊びづらい状態でした。
3. ロビー機能やルーム一覧が作れない
「今誰が部屋を立てて待っているか」を一覧で見たり、合言葉（プライベートルームキー）でサッと入室したりする仕組みが実現できませんでした。

2. 辿り着いた「Oracle Cloud 専用サーバー ＋ ホスト権威同期」のハイブリッド設計

そこで、「以前作った『ホストがマスターデータを持って盤面を絶対同期する仕組み』の良さはそのまま残しつつ、接続とマッチングの窓口だけをクラウド上の専用サーバーに任せる」というハイブリッド構成へ進化させました。

・インフラ：Oracle Cloud（Always Free枠のUbuntuサーバー）に自作C++サーバーを24時間常駐
・通信プロトコル：生の TCP ソケット通信（独自バイナリパケット設計）
・役割分担（ハイブリッド設計）：
1. クラウドサーバー側（窓口・ロビー＆リレー担当）：
固定のパブリックIPで24時間待機し、ロビーの部屋一覧表示、プライベートルーム作成・合言葉（キー）認証、1P/2Pの自動割り当て、先攻・後攻ダイスの公平な抽選、そしてパケットの中継（リレー）を担当します。
2. クライアント側（以前のホスト権威ロジックを継承）：
普段の操作は軽いアクションパケット（CS_MovePiece や CS_DiceResult）を送りつつ、要所で 1P（ホスト）が持つマスター盤面データ（SC_WorldSync）をサーバー経由で 2P へ配信し、ズレを強制補正します。

この構成に進化させて良かったこと

1. ポート開放もIP手入力も完全にゼロになった
1Pも2Pも「Oracle Cloud の固定IP」に接続しにいくだけなので、ルーター設定やIPアドレスの共有が一切不要になり、ボタンひとつで部屋作成・検索・合言葉入室ができるようになりました。

2. 以前作った「盤面の絶対同期」ロジックをそのまま活かせた
すべてのゲーム計算をLinuxサーバー側に書き直すのではなく、サーバーは軽量なリレーとマッチングに徹し、盤面のマスターデータは引き続き1P（ホスト）が持つ設計にしたことで、開発コストを最小限に抑えつつ完璧な同期を実現できました。

3. TCP通信ならではの確実性と自前プロトコルの学び
ターン制のボードゲームでは1つのパケット落ちや順序逆転も許されないため、到達保証・順序保証のある TCP を採用しました。PacketHeader（サイズとパケット種別）を先頭につけ、ストリーム通信特有のパケット結合・分断をバッファリングで切り分ける実装など、ネットワークプログラミングの核心部分を自分の手で組み上げることができました。

3. 実際に作って感じた苦労と学び

クラウド経由の通信に切り替えたあと一番ハマったのは、「ローカル（1人プレイ）や直結テストでは完璧に動いていた処理が、サーバー中継を挟むと微妙なタイミングのズレでバグる」という点でした。

・ダイスを振るアニメーションの1秒間の間に次のパケットが届いて状態が上書きされる
・2Pがダイスを振った直後にホストの古いマスター盤面データが返ってきてワープする
・ターン終了の通知と次の行動の順序が逆転する

これらを1つずつログと動画で追いかけ、「どのタイミングで誰がマスターデータ（正本）を確定させるのか」「アニメーション中は上書きをどう制御するのか」を整理していく過程は、単なるゲーム制作以上のシステム設計の経験になりました。

まとめ

最初は「ホストPCのポート開放＋IP直打ち」というリッスンサーバー型からスタートしましたが、そこから「クラウド上の専用サーバー（Oracle Cloud）を窓口＆リレー役に据え、盤面のマスター同期は1Pホストに任せる」というハイブリッド型へ進化させたことで、コスト0円・ポート開放不要・同期ズレなしの快適なオンライン対戦環境が完成しました。

次の記事では、実際にこのサーバーを動かしている Oracle Cloud の無料構築手順を解説します！

【第3回：Oracle Cloud 構築手順編】
====================================================================

タイトル：
【完全無料】自作オンラインゲームのサーバーをOracle Cloud (OCI) で24時間公開する手順

本文：
個人開発でオンライン対戦ゲームを作ったとき、一番の壁になるのが「対戦用サーバーをどこに置くか？」です。

自分のPCでサーバーを立ち上げると、PCを閉じたら遊べなくなりますし、ルーターのポート開放やグローバルIPの公開などセキュリティ面の不安もあります。かといって有料のVPSを借りると毎月お金がかかります。

そこでおすすめなのが Oracle Cloud Infrastructure (OCI) の「Always Free（ずっと無料枠）」です。

クレジットカード登録は必要ですが、無料枠の範囲内で使っている限り請求は0円。しかも他社のクラウドと違い、無料期間が終わっても自動で課金されることはありません（アップグレードボタンを押さない限り永遠に無料です）。

今回は、自作ゲームの専用サーバー（TCP/UDP通信サーバー）を Oracle Cloud 上に立てて、外部から接続できるようにするまでの手順をまとめます。

1. Oracle Cloud アカウントの作成

まずは Oracle Cloud の公式サイトから無料アカウントを作成します。

1. 「Oracle Cloud Free Tier」で検索し、公式サイトから「無料で開始」をクリック。
2. 名前・メールアドレス・国（Japan）を入力し、メール認証を完了させる。
3. ホームリージョン（Home Region）を選択する。
日本から接続するゲームなら「Japan East (Tokyo)」または「Japan Central (Osaka)」を選びます（※後から変更できないので注意！）。
4. 住所・電話番号・クレジットカード情報を入力して登録完了。
本人確認のため一時的に少額（100円前後）の決済枠確保が行われますが、すぐに返金されます。

2. 無料サーバー（インスタンス）を作成する

アカウントができたら、ゲームサーバーを動かすための仮想マシン（コンピュート・インスタンス）を作ります。

1. 左上のハンバーガーメニュー（≡）から「コンピュート」＞「インスタンス」を開く。
2. 「インスタンスの作成」をクリック。
3. 名前（例: GameServer）を適当に入力。
4. イメージとシェイプを選ぶ（ここが一番重要！）：
・イメージ：Canonical Ubuntu 22.04 または 24.04（Linuxの定番。情報が一番多いです）
・シェイプ：「Always Free対象」と書かれているものを選びます。
軽量なC++サーバーなら VM.Standard.E2.1.Micro（AMD / 1GBメモリ）で十分動きます。
より高いスペック（最大4コア / 24GBメモリ）が欲しい場合は Ampere（Arm系）の VM.Standard.A1.Flex も無料枠で使えます。
5. SSHキーの追加：
「SSHキー・ペアの生成」を選び、「秘密キーの保存（.key ファイル）」を必ずダウンロードして安全な場所に保管します。これがないとサーバーにログインできません。
6. 「作成」をクリックし、ステータスが緑色の「実行中」になればサーバー誕生です！
画面に表示されている「パブリックIPアドレス」をメモしておきます（これがゲームの接続先IPになります）。

3. ファイアウォール（ポート開放）の設定

ここがゲームサーバー構築で一番ハマりやすいポイントです。
Oracle Cloud では、「クラウド側のセキュリティリスト」と「Ubuntu側のファイアウォール」の2箇所でゲーム用ポート（例: 7777番など）を開ける必要があります。

① Oracle Cloud 管理画面側の設定
1. インスタンス詳細画面の「プライマリVNIC」にある「サブネット」のリンクをクリック。
2. 「セキュリティ・リスト」の「Default Security List...」をクリック。
3. 「イングレス・ルールの追加」を押し、以下のように入力：
・ソースCIDR：0.0.0.0/0（世界中のプレイヤーから接続を許可）
・IPプロトコル：TCP（UDPを使う場合は UDP も追加）
・宛先ポート範囲：7777（自作サーバーで使っているポート番号）

② Ubuntu（サーバー内部）側の設定
後ほど SSH でサーバーに入ったあと、Ubuntu 側の通信許可（iptables）も開けます。

（コマンド例）
sudo iptables -I INPUT -p tcp --dport 7777 -j ACCEPT
sudo netfilter-persistent save

※ Ubuntu 標準の ufw ではなく iptables で制御されているのが Oracle Cloud の特徴です。

4. サーバーへログインしてプログラムを配置・ビルドする

Windows なら PowerShell やコマンドプロンプトから ssh コマンドでログインできます。

（コマンド例）
ssh -i ダウンロードした秘密鍵.key ubuntu@メモしたパブリックIP

ログインできたら、C++ のコンパイラ（g++）をインストールしてサーバープログラムをビルドします。

（コマンド例）
sudo apt update
sudo apt install -y g++ make git
g++ -O2 -pthread ServerMain.cpp -o GameServer

5. SSHを閉じても24時間動き続けるようにする

普通に ./GameServer で起動すると、自分のPCのSSH画面を閉じた瞬間にサーバーも終了してしまいます。
バックグラウンドで常駐させるには nohup や screen、あるいは systemd（サービス化）を使います。

手軽に試すなら nohup が一番簡単です。

（コマンド例）
nohup ./GameServer > server.log 2>&1 &
ps aux | grep GameServer

これで SSH のウィンドウを閉じても、PCの電源を切っても、Oracle Cloud 上でゲームサーバーが24時間365日動き続けます！

まとめ

・Oracle Cloud の Always Free 枠を使えば、維持費0円で専用ゲームサーバーを持てる。
・ポート開放は「セキュリティリスト（Web画面）」と「iptables（Ubuntu側）」の2段階で行うのがコツ。
・サーバーIPをクライアント側の接続先に指定すれば、離れた友達同士でもすぐにオンライン対戦ができる！
